# 团队速率跟踪模板

## 模板说明
团队速率（Velocity）是衡量团队在一个迭代中能够完成的故事点数量，用于预测未来迭代的产能和规划发布计划。

## 使用场景
- 每个迭代结束后更新
- 迭代计划时参考历史速率
- 发布计划时预测交付时间
- 团队改进效果评估

## 使用说明

### 如何更新速率数据

**每个迭代结束后：**
1. 记录本迭代的承诺和完成故事点
2. 计算完成率和人均速率
3. 更新速率统计和趋势分析
4. 记录影响因素
5. 更新发布计划预测

### 如何使用速率数据

**迭代计划时：**
- 参考平均速率或中位数速率
- 考虑已知的影响因素
- 不要过度承诺

**发布计划时：**
- 使用保守估计（平均值 - 标准差）
- 考虑风险缓冲
- 定期更新预测

**团队改进时：**
- 分析速率波动原因
- 识别改进机会
- 跟踪改进效果

### 责任人
- **Scrum Master：** 维护速率数据，分析趋势
- **Product Owner：** 使用速率数据规划发布
- **团队：** 提供影响因素信息

## 注意事项

### 速率使用的误区

❌ **错误做法：**
1. 用速率考核团队或个人
2. 强制要求速率持续增长
3. 不同团队之间比较速率
4. 为了提高速率而降低质量
5. 忽略速率波动的原因

✅ **正确做法：**
1. 速率是规划工具，不是考核指标
2. 追求速率稳定，而非持续增长
3. 只在团队内部使用速率数据
4. 平衡速率和质量
5. 分析并改进影响速率的因素

### 速率稳定性的重要性

**稳定的速率比高速率更重要：**
- 可预测性高，便于规划
- 质量有保障
- 团队可持续发展

**如何保持速率稳定：**
- 保持团队稳定
- 控制技术债务
- 持续改进流程
- 避免过度承诺

## 附录：计算公式

### 基本公式

**完成率：**
```
完成率 = (完成故事点 / 承诺故事点) × 100%
```

**人均速率：**
```
人均速率 = 完成故事点 / 团队规模
```

**平均速率：**
```
平均速率 = Σ(完成故事点) / 迭代数量
```

**标准差：**
```
标准差 = √[Σ(完成故事点 - 平均速率)² / 迭代数量]
```

**变异系数：**
```
变异系数 = (标准差 / 平均速率) × 100%
```

### 预测公式

**简单移动平均（SMA）：**
```
预测速率 = (最近N个迭代的完成故事点之和) / N
```

**加权移动平均（WMA）：**
```
预测速率 = (W1×V1 + W2×V2 + W3×V3) / (W1 + W2 + W3)
其中：W为权重，V为速率，最近的迭代权重更高
```

**发布预测：**
```
预计迭代数 = 剩余故事点 / 预测速率
预计完成日期 = 当前日期 + (预计迭代数 × 迭代长度)
```
