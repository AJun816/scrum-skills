# 团队共享文档机制

**本文件定义技能组如何共享工作成果，避免重复劳动**

## 🎯 核心理念

**一次产出，多次使用 - 避免重复整理和分析**

### 问题场景

❌ **错误做法：**
```
产品经理：整理需求 → 产出需求文档
架构师：重新整理需求 → 设计架构
开发人员：再次整理需求 → 开始编码
测试人员：又一次整理需求 → 编写测试
```

✅ **正确做法：**
```
产品经理：整理需求 → 产出需求文档 → 保存到共享目录
架构师：读取需求文档 → 设计架构 → 保存架构文档
开发人员：读取需求+架构文档 → 开始编码
测试人员：读取需求文档 → 编写测试用例
```

## 📋 文档类型和责任技能

**产出时机：**

## 🎯 关键优势

### 1. 避免重复劳动

❌ **传统方式：**
- 产品经理整理需求 → 1000 tokens
- 架构师重新整理需求 → 1000 tokens
- 开发人员再次整理需求 → 1000 tokens
- 测试人员又一次整理需求 → 1000 tokens
- **总计：4000 tokens**

✅ **共享文档方式：**
- 产品经理整理需求 → 1000 tokens（产出文档）
- 架构师读取文档 → 100 tokens
- 开发人员读取文档 → 100 tokens
- 测试人员读取文档 → 100 tokens
- **总计：1300 tokens（节约67.5%）**

### 2. 保证一致性

- 所有技能基于相同的需求文档工作
- 避免理解偏差和信息不一致
- 需求变更时只需更新一份文档

### 3. 提高效率

- 技能可以直接使用前置技能的产出
- 减少等待和沟通成本
- 加快开发进度

### 4. 模拟真实团队

- 真实敏捷团队也是共享文档的
- 符合敏捷开发的协作模式
- 提供更真实的团队协作体验

## 📝 技能实施指南

### 产出文档的技能

**必须做：**
1. 产出文档后保存到共享目录
2. 更新索引文件
3. 通知团队文档已就绪

**文档格式：**
- 使用Markdown格式
- 包含标题、摘要、详细内容
- 标注创建时间和创建者

### 使用文档的技能

**必须做：**
1. 先查看索引，找到相关文档
2. 读取文档内容
3. 基于文档内容执行任务
4. 不要重新整理已有的信息

**读取顺序：**
1. 查看总索引 `SHARED_INDEX.md`
2. 找到相关文档路径
3. 读取具体文档
4. 开始工作

## 总结

**团队共享文档机制的核心价值：**

1. **一次产出，多次使用** - 避免重复劳动
2. **保证一致性** - 所有技能基于相同信息工作
3. **提高效率** - 减少Token消耗和等待时间
4. **真实协作** - 模拟真实敏捷团队的工作方式

**让技能组像真正的敏捷团队一样，共享知识，高效协作。**
