# 代码质量检查标准

**本文件定义技能组的代码质量标准和检查机制**

## 核心原则

1. **代码质量优先**：质量比速度更重要
2. **自动化检查**：开发完成后自动进行质量检查
3. **多层次保障**：开发自检 + 架构师审查 + 测试验证
4. **持续改进**：识别问题，持续优化代码质量

## 代码质量标准

### 1. 编码规范

**后端代码（Java）：**
- 遵循《代码简洁之道》(Clean Code) 原则
- 类名：大驼峰命名（PascalCase），如 `UserService`
- 方法名：小驼峰命名（camelCase），如 `getUserById`
- 变量名：小驼峰命名，语义清晰，如 `userName`
- 常量名：全大写+下划线，如 `MAX_RETRY_COUNT`
- 包名：全小写，如 `com.project.domain.user`
- 单个方法不超过50行
- 单个类不超过500行
- 方法参数不超过5个
- 避免深层嵌套（最多3层）

**前端代码（Vue/TypeScript）：**
- 组件名：大驼峰命名（PascalCase），如 `UserProfile.vue`
- 方法名：小驼峰命名（camelCase），如 `handleSubmit`
- 变量名：小驼峰命名，语义清晰，如 `userName`
- 常量名：全大写+下划线，如 `API_BASE_URL`
- 单个组件不超过300行
- 单个方法不超过30行
- 避免深层嵌套（最多3层）
- 使用TypeScript类型注解

### 2. 代码结构

**后端代码（DDD架构）：**
- 领域层（domain）：领域模型、值对象、领域服务
- 应用层（application）：应用服务、DTO
- 接口层（interfaces）：Controller、DTO转换
- 基础设施层（infrastructure）：Repository实现、外部服务

**前端代码（Vue 3）：**
- views：页面组件
- components：可复用组件
- composables：组合式函数
- stores：状态管理（Pinia）
- api：API接口封装
- utils：工具函数

### 3. 注释和文档

**必须添加注释的场景：**
- 类和接口：说明职责和用途
- 公共方法：说明参数、返回值、异常
- 复杂逻辑：说明算法思路和业务规则
- 魔法数字：说明含义

**注释规范：**
- 使用中文注释
- 注释要简洁、准确、有价值
- 避免无意义的注释（如 `// 获取用户` 对应 `getUser()`）
- 及时更新注释，保持与代码同步

### 4. 异常处理

**后端异常处理：**
- 使用自定义业务异常
- 统一异常处理机制
- 异常信息清晰、可追溯
- 记录异常日志

**前端异常处理：**
- API调用统一错误处理
- 用户友好的错误提示
- 异常上报机制

### 5. 日志记录

**日志级别：**
- ERROR：错误信息，需要立即处理
- WARN：警告信息，可能存在问题
- INFO：关键业务流程信息
- DEBUG：调试信息（生产环境关闭）

**日志规范：**
- 关键业务操作必须记录日志
- 日志信息清晰、完整
- 包含必要的上下文信息（用户ID、请求ID等）
- 避免记录敏感信息（密码、身份证号等）

### 6. 性能优化

**后端性能：**
- 避免N+1查询
- 合理使用缓存
- 数据库索引优化
- 避免大事务

**前端性能：**
- 组件懒加载
- 图片懒加载
- 防抖和节流
- 避免不必要的重渲染

### 7. 安全编码

**必须防范的安全问题：**
- SQL注入：使用参数化查询
- XSS攻击：输入验证和输出转义
- CSRF攻击：使用CSRF Token
- 敏感信息泄露：不在日志中记录敏感信息
- 权限控制：接口级别的权限验证

## 质量指标

### 代码质量指标

**必须达到的指标：**
- 单元测试覆盖率 ≥ 80%
- 代码审查通过率 = 100%
- 测试通过率 ≥ 95%
- 代码重复率 ≤ 5%
- 代码复杂度 ≤ 10（圈复杂度）

### 性能指标

**必须达到的指标：**
- API响应时间 ≤ 500ms（P95）
- 页面加载时间 ≤ 2s
- 数据库查询时间 ≤ 100ms
- 前端首屏渲染时间 ≤ 1s

### 安全指标

**必须达到的指标：**
- 无高危安全漏洞
- 无中危安全漏洞
- 低危安全漏洞 ≤ 5个

## 质量问题处理

### 问题分级

**P0（严重）：**
- 功能完全不可用
- 数据丢失或损坏
- 严重安全漏洞
- 系统崩溃

**处理：** 立即修复，阻塞发布

**P1（重要）：**
- 核心功能异常
- 性能严重下降
- 中危安全漏洞

**处理：** 优先修复，当前迭代完成

**P2（一般）：**
- 非核心功能异常
- 代码质量问题
- 低危安全漏洞

**处理：** 计划修复，下个迭代完成

**P3（轻微）：**
- UI小问题
- 代码优化建议

**处理：** 择机修复

## 总结

通过多层次的代码质量检查机制，技能组确保：

1. **开发自检**：开发人员对代码质量负责
2. **架构师审查**：确保代码符合架构设计和编码规范
3. **测试验证**：确保功能正确性和质量指标达标
4. **持续改进**：识别问题，持续优化代码质量

**让技能组像真正的专业团队一样，始终保持高质量的代码交付。**
