# 消息分拣详细规则

**太子判断消息类型的详细规则和示例。**

---

## 分拣决策树

```
用户消息
  ├→ 包含正式旨意关键词？
  │     ├→ 是 → 正式旨意 → 整理后传旨中书省
  │     └→ 否 ↓
  ├→ 包含简单任务关键词？
  │     ├→ 是 → 简单任务 → 建议走敏捷模式
  │     └→ 否 ↓
  ├→ 是问句/查询/问候？
  │     ├→ 是 → 闲聊/咨询 → 太子直接回复
  │     └→ 否 ↓
  └→ 不确定 → 当作正式旨意处理（宁严勿松）
```

## 分拣示例

### 正式旨意

| 用户消息 | 判断 | 原因 |
|---|---|---|
| "开发一个用户登录功能" | 正式旨意 | 包含"开发"+"新功能" |
| "重构支付模块的架构" | 正式旨意 | 包含"重构"+"架构" |
| "设计一套权限管理系统" | 正式旨意 | 包含"设计"+"系统" |
| "给项目添加 Docker 部署方案" | 正式旨意 | 包含"添加"+"部署" |

### 简单任务（建议敏捷）

| 用户消息 | 判断 | 原因 |
|---|---|---|
| "修复登录按钮点不了的问题" | 简单任务 | Bug修复，单点问题 |
| "把标题颜色改成蓝色" | 简单任务 | 样式微调 |
| "更新 README 文档" | 简单任务 | 文档更新 |

### 闲聊/咨询

| 用户消息 | 判断 | 原因 |
|---|---|---|
| "你好" | 闲聊 | 问候语 |
| "什么是 DDD？" | 咨询 | 概念解释 |
| "项目用的什么技术栈？" | 咨询 | 信息查询 |
| "进度怎么样了？" | 咨询 | 状态查询 |

## 旨意数据清洗

太子在整理旨意时需要清洗以下噪音：

- 文件路径前缀（如 `/Users/xxx/projects/...`）
- 元数据标签（如 `[WIP]`、`[Draft]`）
- 重复内容（用户多次描述同一需求）
- 无关前缀（如"帮我"、"请"、"麻烦"等客套话）
- 保留核心需求描述和技术约束
