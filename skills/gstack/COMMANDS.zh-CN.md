# gstack 中文命令目录

本文件是 vendored `gstack` 的中文入口说明，目的是让用户快速知道“命令是干什么的、什么时候用、有没有额外依赖”。

## 使用前提

1. 先完成 gstack 自身 setup：`<agent-home>/skills/gstack/setup`
2. gstack 属于可选扩展，不影响 Scrum Skills 核心技能组安装
3. gstack 完整启用需要 `bun >= 1.0`；部分命令还会依赖浏览器或 Playwright

## 规划与思考

| 命令 | 作用 | 何时使用 |
|------|------|----------|
| `/office-hours` | 用 YC Office Hours 风格拷问问题、需求和产品方向 | 新想法、产品脑暴、判断值不值得做 |
| `/autoplan` | 自动整理执行计划和任务拆解 | 需求比较散，需要先收敛成计划 |
| `/plan-ceo-review` | 用 CEO 视角审计划，关注目标、风险、收益 | 方案准备立项或拉齐方向时 |
| `/plan-eng-review` | 用工程视角审计划，关注实现成本和技术风险 | 开发前做技术可行性把关 |
| `/plan-design-review` | 用设计视角审计划，提前挑出 UI/UX 风险 | 有页面或交互方案时 |
| `/design-consultation` | 做设计咨询和方向建议 | 还在探索视觉/交互方案时 |
| `/design-review` | 审查现有页面或交互设计质量 | 页面已经有原型或实际界面时 |
| `/careful` | 切换到更保守、更审慎的执行节奏 | 任务风险高、改动代价大时 |
| `/cso` | 从安全/风控视角审查方案 | 涉及权限、数据、外部暴露面时 |

## 调研与排障

| 命令 | 作用 | 何时使用 |
|------|------|----------|
| `/browse` | 用无头浏览器打开站点、操作页面、留证据 | 需要真实浏览器验证页面时 |
| `/investigate` | 深挖问题根因，给出排查链路 | 遇到难复现 Bug、异常行为时 |
| `/benchmark` | 做性能/基准对比 | 需要量化前后性能差异时 |
| `/canary` | 小范围验证改动是否安全 | 上线前想先做小流量或最小验证时 |
| `/setup-browser-cookies` | 配置浏览器 Cookies，便于后续自动化访问 | 浏览器测试需要登录态时 |
| `/codex` | 用 gstack 语义桥接 Codex 风格工作流 | 在 Codex 场景下想复用 gstack 习惯时 |

## 评审、QA 与发布

| 命令 | 作用 | 何时使用 |
|------|------|----------|
| `/review` | 做代码变更评审，检查结构性风险 | 提交、合并、落地前 |
| `/qa` | 系统化测 Web 应用并迭代修问题 | 功能完成后做真实 QA 时 |
| `/qa-only` | 只做 QA 报告，不自动修复 | 先要测试结论，不想立即改代码时 |
| `/ship` | 执行提测/提 PR/推送前的一整套 ship 流程 | 代码准备交付时 |
| `/land-and-deploy` | 合并并部署 | 需要把变更真正落到环境时 |
| `/document-release` | 补版本说明和发布文档 | 发版前需要整理变更说明时 |
| `/retro` | 做复盘，总结做得好/差/待改进 | 一个阶段结束后 |

## 运行控制

| 命令 | 作用 | 何时使用 |
|------|------|----------|
| `/freeze` | 冻结发布或变更节奏 | 上线窗口、事故期、稳定性风险期 |
| `/unfreeze` | 解除冻结，恢复正常推进 | 风险解除后 |
| `/guard` | 持续盯住某个高风险事项 | 需要长期观察风险点时 |
| `/setup-deploy` | 初始化部署相关配置 | 第一次接入部署链路时 |
| `/gstack-upgrade` | 升级 gstack 自身 | 上游有新版本，需要同步时 |

## 调用建议

- 只想做代码质量把关：优先 `/review`
- 只想做站点测试：优先 `/qa` 或 `/qa-only`
- 还没开始写代码：优先 `/office-hours`、`/plan-eng-review`、`/plan-design-review`
- 要上线：优先 `/ship`，需要实际发布再看 `/land-and-deploy`

## 依赖边界

- Scrum Skills 核心安装不要求 bun
- 只有你显式启用 gstack 时，才需要按它自己的 setup 安装依赖
- 浏览器相关命令的浏览器/Playwright 依赖由 gstack 自己处理，不写进核心安装器
