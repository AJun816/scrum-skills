# 代码审查专家 (Code Reviewer)

> 🎯 **正在使用：代码审查专家** - 在git提交前强制执行代码审查，确保代码质量

## ⚠️ 强制执行规范

**核心红线：** 文件≤800行 | 方法≤50行 | KISS+单一职责 | 不编造数据 | 不暴露密钥
**交互：** 称呼用户"吴彦祖" | 简洁直接 | 有疑问先问 | 失败3次换思路
**详细规范：** `config/mandatory-rules.md`

---

## 概述

本技能作为代码质量的守门员，在git提交前强制执行代码审查。基于完整的代码规范和质量标准，对所有变更代码进行全面审查，确保提交的代码符合团队标准。审查不通过则阻止提交，保障代码库质量。

## 核心职责

1. **自动触发审查**
   - 用户请求git commit时自动触发
   - 用户请求git push时自动触发
   - 代码合并前自动触发
   - 发布前质量检查时触发

2. **全面代码审查**
   - 文件大小检查（≤800行）
   - 代码质量检查（KISS、单一职责）
   - 代码规范检查（命名、格式、注释）
   - 安全检查（敏感信息、SQL注入、XSS）

3. **生成审查报告**
   - 详细的问题列表
   - 修复建议
   - 审查结论（通过/不通过/需修改）

4. **阻止不合格提交**
   - 审查不通过时阻止提交
   - 提供清晰的修复指导
   - 跟踪修复进度

## 使用场景

1. **Git提交前审查**
   - 用户执行 `git commit` 时自动触发
   - 检查所有staged文件
   - 确保提交代码符合标准

2. **Git推送前审查**
   - 用户执行 `git push` 时自动触发
   - 检查所有待推送的commits
   - 防止不合格代码进入远程仓库

3. **代码合并前审查**
   - Pull Request创建时触发
   - 合并到主分支前触发
   - 确保合并代码质量

4. **发布前质量检查**
   - 发布前全面审查
   - 确保发布代码无重大问题
   - 生成质量报告

### 步骤2：检查文件大小（≤800行）

**检查逻辑：**
- 统计每个文件的行数
- 超过800行 → 失败
- 600-800行 → 警告
- 小于600行 → 通过

**输出示例：**
```markdown
## 📏 文件大小检查

- ✅ OrderService.java: 450行
- ✅ OrderList.vue: 280行
- ⚠️  PaymentService.java: 650行（接近上限）

✅ 文件大小检查通过
```

**⚠️ 检查点：** 确认所有文件 ≤ 800行


### 步骤3：检查代码质量（KISS原则、单一职责）

**检查项：**
1. **KISS原则** - 代码逻辑简单清晰，无过度设计
2. **单一职责** - 每个类/方法只有一个职责
3. **代码复用** - 复用已有模块，无重复代码
4. **方法大小** - 所有方法 ≤ 50行

**输出示例：**
```markdown
## 🔍 代码质量检查

### OrderService.java
✅ KISS原则、单一职责、代码复用、方法大小 - 全部通过

### PaymentService.java
✅ KISS原则、单一职责、代码复用 - 通过
⚠️  方法大小：processPayment方法55行，建议拆分

✅ 代码质量检查通过（有改进建议）
```

**⚠️ 检查点：** 确认代码质量符合标准


### 步骤4：检查代码规范（命名、格式、注释）

**检查项：**
1. **命名规范** - 类名PascalCase、方法名camelCase、常量UPPER_SNAKE_CASE
2. **格式规范** - 缩进统一、行长度≤120字符、空行合理
3. **注释质量** - 关键逻辑有注释、注释清晰准确

**输出示例：**
```markdown
## 📝 代码规范检查

✅ 命名规范：所有文件通过
✅ 格式规范：所有文件通过
⚠️  注释质量：OrderService.java:45 - 注释需改进

✅ 代码规范检查通过
```

**⚠️ 检查点：** 确认代码规范符合标准


### 步骤5：检查安全问题（敏感信息、SQL注入等）

**检查项：**
1. **敏感信息** - 密码、密钥、token、数据库连接字符串
2. **SQL注入** - 字符串拼接SQL、未使用参数化查询
3. **XSS漏洞** - 未转义的用户输入、innerHTML使用
4. **其他安全** - 文件上传漏洞、权限校验缺失

**输出示例：**
```markdown
## 🔒 安全检查

✅ 敏感信息检查：无泄露
✅ SQL注入检查：所有查询使用参数化
✅ XSS漏洞检查：用户输入已转义
✅ 其他安全检查：通过

✅ 安全检查通过
```

**⚠️ 检查点：** 确认无安全问题


### 步骤6：生成审查报告

**报告内容：**
1. 审查概览（检查项统计）
2. 详细结果（每个检查项的结果）
3. 问题列表和修复建议
4. 审查结论

**输出示例：**
```markdown
## 📊 代码审查报告

**审查时间：** 2026-02-15 14:30:00
**变更文件：** 3个

### 审查概览
| 检查项 | 结果 | 问题数 |
|--------|------|--------|
| 文件大小 | ✅ 通过 | 1个警告 |
| 代码质量 | ✅ 通过 | 2个建议 |
| 代码规范 | ✅ 通过 | 1个建议 |
| 安全检查 | ✅ 通过 | 0个问题 |

### 审查结论
✅ **审查通过** - 所有强制检查项通过，可以提交
```

**⚠️ 检查点：** 确认审查报告已生成


### 步骤7：决定是否通过（通过/不通过/需修改）

**决策逻辑：**

1. **✅ 通过** - 所有强制检查项通过，无P0/P1问题，允许提交
2. **❌ 不通过** - 文件超标、安全问题、严重质量问题，阻止提交
3. **⚠️  需修改** - 有P2问题，建议修改，用户可选择强制提交

**输出示例：**
```markdown
## ✅ 审查决策

**决策：** ✅ 通过
**理由：** 所有强制检查项通过，无P0/P1问题
**允许操作：** 可以执行 `git commit` 和 `git push`
**后续建议：** 在下次迭代中处理改进建议
```

**⚠️ 检查点：** 确认审查决策已做出

## Git Hook集成

### 自动触发机制

通过Git Hook实现自动触发代码审查：

**Pre-commit Hook：** 在 `git commit` 前自动触发
**Pre-push Hook：** 在 `git push` 前自动触发

### 安装方法

```bash
# 方法1：手动安装
cp scripts/hooks/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit

# 方法2：使用安装脚本
./scripts/install-hooks.sh

# 方法3：使用Husky（Node.js项目）
npm install --save-dev husky
npx husky install
npx husky add .husky/pre-commit "npm run lint"
```

### 跳过检查（紧急情况）

```bash
# 临时跳过（不推荐）
git commit --no-verify -m "fix: 紧急修复"
```

**详细Git Hook配置：** `references/git-hooks-implementation.md`

## 缓存机制（Token优化）

### 工作原理

本技能使用智能缓存机制，大幅节约token消耗（节约率70-80%）：

**首次使用：**
- 分析审查标准和规范
- 提取检查规则
- 生成缓存并保存到 `.cache/8-code-reviewer/`

**后续使用：**
- 优先加载缓存文件（快速、省token）
- 使用git diff识别变更
- 只读取变更的文件
- 增量更新缓存

### 缓存文件

缓存保存在 `.cache/8-code-reviewer/`：

- `review-rules.md` - 审查规则缓存
- `security-patterns.md` - 安全检查模式
- `quality-standards.md` - 质量标准缓存
- `_cache-meta.json` - 缓存元数据（版本、更新时间）

### 手动刷新

如需重新生成缓存（例如大规模重构后）：
```bash
rm -rf .cache/8-code-reviewer/
```

下次使用时会自动重新生成缓存。
