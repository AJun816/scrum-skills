# 敏捷团队技能组风格标准

## 技能命名和目录结构

**必须遵守的命名规范：**

1. **目录名称：** `{编号}-{英文名称}`
   - 示例：`8-security-expert`、`9-data-analyst`

2. **SKILL.md 的 name 字段：** 与目录名称完全一致
   ```yaml
   ---
   name: 8-security-expert
   ---
   ```

3. **description 字段：** 以【编号】开头
   ```yaml
   ---
   description: 【8】安全专家，负责系统安全评估...
   ---
   ```

4. **缓存目录：** `skills/.cache/{编号}-{英文名称}/`
   - 示例：`skills/.cache/8-security-expert/`

## SKILL.md 结构模板

```markdown
---
name: {编号}-{英文名称}
description: 【{编号}】{中文名称}，负责{职责描述}。当{使用场景1}、{使用场景2}、或{使用场景3}时使用。本技能{详细说明}。

## ⚠️ 强制执行规范（必读）

**在开始任何工作前，必须遵守以下规范：**

### 代码质量红线（最高优先级）

**文件大小：**
- ❌ 禁止：单个文件超过 800 行
- ✅ 必须：超过 600 行立即考虑拆分
- ✅ 必须：发现超标立即停止，先重构再继续

**方法大小：**
- ❌ 禁止：单个方法超过 50 行
- ✅ 必须：超过 30 行考虑拆分

**设计原则：**
- ✅ 必须：遵循 KISS 原则（保持简单）和单一职责原则
- ✅ 必须：代码变更范围最小化
- ✅ 必须：优先复用已有代码
- ❌ 禁止：引入不必要的依赖
- ❌ 禁止：破坏原有功能

**数据使用：**
- ✅ 必须：使用真实数据，不编造信息
- ❌ 禁止：暴露敏感信息（密码、密钥、token）

### 强制检查点

**检查点1：任务开始前**
- [ ] 已分析现有代码库结构
- [ ] 已读取架构文档（如有）
- [ ] 已确认任务目标和范围

**检查点2：编码前**
- [ ] 已读取目标文件，确认当前行数：___行
- [ ] 已确认修改不会导致文件超标（>800行）

**检查点3：编码中（每完成一个类/方法）**
- 文件行数：___行（必须 ≤ 800行）
- 方法行数：___行（必须 ≤ 50行）
- 如超标 → 立即停止 → 重构 → 继续

**检查点4：编码后**
- [ ] 所有文件 ≤ 800行
- [ ] 所有方法 ≤ 50行
- [ ] 代码逻辑正确，已自检

### 交互原则

- 称呼用户为"吴彦祖"
- 联系前文内容，避免重复询问
- 有疑问先询问，不擅自做重大决定
- 回复简洁直接，避免冗余

**完整规范参考：** `skills/.mandatory-standards.md`
```

## 关键风格要点

1. **中文优先**
   - 所有说明使用中文
   - 技术术语可保留英文，但建议添加中文解释
   - description 字段使用中文，包含【编号】标记

2. **强制执行规范统一**
   - 所有技能必须在前50行包含强制执行规范
   - 代码质量红线放在最前面
   - 强制检查点嵌入工作流程

3. **执行标准统一**
   - 所有技能必须引用 `.skill-execution-standard.md`
   - 所有技能必须引用 `.data-verification-standard.md`
   - 所有技能必须引用 `.mandatory-standards.md`

4. **团队协作机制**
   - 必须包含"团队协作"部分
   - 说明主动介入时机
   - 说明主动寻求帮助的场景
   - 说明主动提供帮助的方式

5. **缓存优化**
   - 所有技能必须包含缓存机制说明
   - 说明缓存的工作原理
   - 说明缓存文件的位置和内容
   - 说明如何手动刷新缓存

6. **实时显示**
   - 所有操作必须实时显示进度
   - 使用 emoji 和格式化增强可读性
   - 让用户清楚了解每个步骤

7. **数据验证**
   - 强调"绝不瞎回答"原则
   - 所有回答必须基于真实数据
   - 明确标注数据来源
   - 不确定时明确说明

8. **文件大小控制**
   - SKILL.md 控制在 400-500行
   - 详细内容移到 references/
   - 模板移到 assets/
   - 脚本移到 scripts/
