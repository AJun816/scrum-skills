# 技能执行标准

**本文件定义所有技能的通用执行标准**

## 执行流程

### 第一步：读取项目配置（必需）

**所有技能在执行任务前，必须先读取项目配置：**

```markdown
## 🚀 初始化：{技能名称}

正在加载项目配置...
✅ 读取 PROJECT_CONFIG.md
✅ 项目：{项目名称}
✅ 技术栈：{技术栈}
✅ 业务域：{业务域列表}

配置加载完成，开始执行任务...
```

**读取内容：**
- 项目基本信息（名称、描述、领域）
- 技术栈配置
- 业务域定义
- 架构概览
- 核心业务规则
- 技术约束

**配置文件位置：** `skills/PROJECT_CONFIG.md`

### 第二步：分析任务

```markdown
## 🔍 分析任务

**任务内容：** {用户请求}

**分析结果：**
- 涉及业务域：{domain1}, {domain2}
- 需要读取的文件：{file1}, {file2}
- 预计步骤：{step1}, {step2}, {step3}

开始执行...
```

### 第三步：执行任务（实时显示）

```markdown
## 📋 执行步骤

### 步骤 1/N：{步骤名称}

正在执行：{操作描述}...

{详细过程}

✅ 完成

---

### 步骤 2/N：{步骤名称}

正在执行：{操作描述}...

{详细过程}

✅ 完成

---

### 步骤 N/N：{步骤名称}

正在执行：{操作描述}...

{详细过程}

✅ 完成
```

### 第四步：完成总结

```markdown
## ✅ 任务完成

**完成内容：**
- ✅ {完成项1}
- ✅ {完成项2}
- ✅ {完成项3}

**输出文件：**（如有）
- `{file1}` - {说明}
- `{file2}` - {说明}

**下一步建议：**
- {建议1}
- {建议2}
```

## 执行可见性要求

### 实时显示原则

**所有操作必须实时显示，让用户清楚了解进度：**

- ✅ 显示当前步骤
- ✅ 显示正在读取/分析的文件
- ✅ 显示正在执行的操作
- ✅ 显示进度百分比（如适用）

**禁止：**
- ❌ 默认隐藏执行过程
- ❌ 只显示最终结果
- ❌ 让用户猜测正在发生什么

### 文件操作显示

#### 读取文件

```markdown
📖 **正在读取文件：** `{file_path}`

**原因：** {为什么要读取这个文件}

✅ 读取完成（{行数} 行）
```

#### 写入文件

```markdown
📝 **正在写入文件：** `{file_path}`

**内容：** {写入内容的简要说明}

✅ 写入完成
```

#### 编辑文件

```markdown
✏️ **正在编辑文件：** `{file_path}`

**修改：**
- 第 {line_number} 行：{修改说明}

✅ 编辑完成
```

#### 搜索文件

```markdown
🔍 **正在搜索：** `{search_pattern}`

**搜索范围：** {search_path}

✅ 找到 {count} 个匹配项
```


## 语言规范

### 使用中文

**所有输出使用中文，包括：**
- 提示信息
- 步骤说明
- 错误信息
- 进度显示
- 用户交互

**例外：**
- 代码变量名、函数名（编程规范）
- 文件路径和文件名（系统要求）
- 技术术语缩写（如 API、DDD、CRUD）可保留，但建议添加中文解释

### 技术术语处理

**技术术语使用规范：**

```markdown
✅ 推荐：
- 使用 DDD（领域驱动设计）架构
- 实现 RESTful API 接口
- 采用 SOLID 原则

✅ 也可以（首次出现时解释）：
- 使用 DDD（Domain-Driven Design，领域驱动设计）架构
- 后续可以直接使用 DDD
```

## 技能特定要求

### 0-scrum-master（敏捷教练）

**特殊职责：**
- 首次使用时，检查缓存文件 `.cache/.project-info.json`
- 如果缓存不存在，启动初始化引导流程
- 如果缓存存在，告知用户项目已初始化，直接开始工作

**详细流程参考：** `.init-detection.md` 和 `.init-guide.md`

### 其他技能

**标准流程：**
1. 读取 `PROJECT_CONFIG.md`
2. 加载项目上下文
3. 执行任务
4. 实时显示进度
5. 完成总结

## 缓存机制

### 工作原理

**技能可以使用缓存机制优化 token 消耗：**

**首次使用：**
- 分析项目文件
- 提取关键信息
- 保存到 `.cache/{skill-name}/`

**后续使用：**
- 优先加载缓存文件
- 使用 git diff 识别变更
- 只读取变更的文件
- 增量更新缓存

### 缓存位置

```
skills/.cache/
├── .project-info.json          # 项目初始化信息
├── 0-scrum-master/             # Scrum Master 缓存
├── 1-business-expert/          # 业务专家缓存
├── 2-product-manager/          # 产品经理缓存
├── 3-system-architect/         # 系统架构师缓存
└── ...
```

### 手动刷新

如需重新生成缓存：

```bash
# 清除所有缓存
rm -rf skills/.cache/

# 清除特定技能缓存
rm -rf skills/.cache/{skill-name}/
```

下次使用时会自动重新生成缓存。

## 总结

通过遵循这些执行标准，技能组可以：

1. **统一体验** - 所有技能使用一致的执行流程
2. **实时可见** - 用户清楚了解每个步骤的进度
3. **中文友好** - 所有输出使用中文，易于理解
4. **高效执行** - 通过缓存机制节约 token
5. **易于维护** - 统一标准，便于更新和优化

**核心理念：** 让技能组的工作过程透明、高效、易用。
