# 三省六部完整流转指南

**皇上下旨后的完整流转流程。**

---

## 流转总览

```
👑 皇上 下旨
    ↓
🤴 太子 分拣（闲聊直接回 / 正式旨意传旨）
    ↓
📜 中书省 接旨 → 规划（PM + Architect）
    ↓
🔍 门下省 审核（阶段1: 需求 + 阶段2: 架构）
    ↓ 准奏 / 封驳
📮 尚书省 派发 → 六部并行执行
    ↓
🔍 门下省 审核（阶段3: 代码）
    ↓ 准奏 / 封驳
📜 中书省 回奏
    ↓
👑 皇上 御览 → git commit
```

## 各阶段详解

### 阶段 0：下旨

皇上（用户）描述需求，自动生成旨意：
- 旨意标题
- 旨意内容
- 优先级
- 存入 `.cache/shared/edicts/`

### 阶段 1-2：中书省规划 + 门下省审核

中书省调用 PM 和 Architect 产出：
- 需求文档 → `.cache/shared/requirements/`
- 架构设计 → `.cache/shared/architecture/`
- API 设计 → `.cache/shared/api-design/`

门下省审核以上产出物，决定准奏或封驳。

### 阶段 3：尚书省派发 + 六部执行

尚书省根据任务类型派发到对应六部：
- 后端 → `/4-backend-dev`（Agent 子进程）
- 前端 → `/4-frontend-dev`（Agent 子进程）
- DevOps → `/5-devops-engineer`（Agent 子进程）
- 可并行的任务同时派发

### 阶段 4：门下省代码审核

六部执行完成后，尚书省汇总提交门下省做代码审核。

### 阶段 5：回奏

代码审核通过后，中书省汇总最终报告回奏皇上。

## 御批通道

紧急情况下皇上可御批跳过门下省审核：
- commit message 标注 `[御批]`
- 记录御批原因到 `.cache/shared/review-reports/`

## 叫停机制

皇上可随时输入"叫停"终止当前流程，所有省部立即停止工作。
