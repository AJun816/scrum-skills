# 强制执行规范

**所有技能必须遵守的核心规范，违反即停止工作。**

---

## 代码质量红线

**文件大小：**
- ❌ 禁止：单个文件超过 800 行
- ✅ 必须：超过 600 行立即拆分
- ✅ 必须：发现超标立即停止，先重构再继续

**方法大小：**
- ❌ 禁止：单个方法超过 50 行
- ✅ 必须：超过 30 行考虑拆分

**设计原则：**
- KISS原则：保持简单，避免过度设计
- 单一职责：每个类/方法只做一件事
- 最小变更：只改必要的部分，不顺手改无关代码
- 代码复用：优先复用已有代码，不重复造轮子
- 依赖管理：只引入必要的依赖，优先标准库
- 功能保护：确保不破坏原有功能，验证边界情况

## 数据使用规范

**真实性：**
- ✅ 使用真实数据，基于实际代码和文档回答
- ✅ 明确标注数据来源（文件路径、行号）
- ❌ 禁止编造信息、猜测不确定的内容

**安全性：**
- ✅ 使用环境变量存储密钥
- ❌ 禁止暴露密码、密钥、token
- ❌ 禁止提交敏感信息到版本控制

## 数据验证原则（Read-First）

**所有技能在回答问题前，必须先读取相关文件验证：**

1. **读取验证**：先读取文件，后回答问题
2. **来源追溯**：每个回答标注数据来源（文件路径+行号）
3. **不确定声明**：不确定时明确说明，提供验证方法
4. **防止幻觉**：不基于假设回答，不确定就读取文件确认

## 交互原则

- ✅ 称呼用户为"吴彦祖"
- ✅ 联系前文内容，避免重复询问已知信息
- ✅ 有疑问先询问用户，不擅自做重大决定
- ✅ 回复简洁直接，重点突出，条理清晰
- ❌ 禁止长篇大论、过度解释显而易见的内容

## 任务执行原则

**任务拆解：**
- 复杂需求拆解成小任务，分步实现，逐步验证

**操作确认：**
- 验证性操作（读取、搜索、分析）可自动执行
- 副作用操作（修改、删除、提交、部署）需用户确认

**错误处理：**
- 同一问题连续失败3次后，换思路或询问用户
- 记录失败原因和尝试过的方法

**进度可见性：**
- 实时显示执行进度，使用中文输出
- 让用户了解当前状态，禁止长时间无反馈

## 质量检查点

**编码前：** 读取目标文件确认行数，制定实施方案
**编码中：** 每完成一个类/方法检查行数是否超标
**编码后：** 确认所有文件≤800行、方法≤50行、无安全漏洞

## 编码执行规范（aider 强制要求）

**所有编码型任务（后端/前端/DevOps脚本/Bug修复）必须遵守：**

- ✅ **必须**：通过 aider 命令执行代码编写（生成单行命令，用户在终端执行）
- ✅ **必须**：aider 命令包含 `--no-git` 参数，由主进程统一管理 git
- ✅ **必须**：aider 完成后，由 `/8-code-reviewer` 审查代码，审查通过后才能 git commit
- ✅ **必须**：aider 命令输出为单行（不换行），方便用户直接复制粘贴执行
- ✅ **必须**：aider 命令包含 `--read` 注入相关上下文文档（架构设计、API契约等）
- ❌ **禁止**：跳过 aider 直接用 Edit/Write 工具写代码（aider 不可用时除外，需向用户报告）
- ❌ **禁止**：aider 命令省略 `--architect` 和 `--yes-always` 参数
- ❌ **禁止**：直接执行 git commit，必须先经过代码审查

**aider 不可用时降级策略（必须执行）：**
1. 向用户报告 aider 不可用的原因
2. 经用户确认后，降级使用 Claude Code Edit/Write 工具实现
3. 降级实现同样必须经过 `/8-code-reviewer` 审查后才能 commit

**详细规范参考：** `config/aider-integration.md`
