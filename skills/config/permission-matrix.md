# 权限矩阵

**三省六部模式下的调用权限定义，实现分权制衡。**

---

## 核心原则

1. **皇上至高无上**：皇上可下旨给中书省，中书省回奏给皇上
2. **三省分权**：中书省规划、门下省审核、尚书省派发，互相制衡
3. **六部听令**：六部只接受尚书省派发，只向尚书省回报
4. **门下独立**：门下省独立审核，不受中书省和尚书省干预

## 关键约束

### 皇上（用户）
- 只与太子交互（下旨 + 接收回奏）
- 太子分拣后将正式旨意传给中书省
- 可随时叫停任何流程
- 可御批（直接决策，跳过门下省审核）

### 太子
- 接收皇上所有消息，判断闲聊还是正式旨意
- 闲聊直接回复，正式旨意整理后传旨给中书省
- 简单任务建议走敏捷模式
- 不参与后续流程（传旨后退出）

### 中书省
- 接收皇上旨意，调用 PM 和 Architect 进行规划
- 不能直接调用六部执行层（必须通过尚书省）
- 规划完成后必须提交门下省审核

### 门下省
- 独立审核，不受其他省干预
- 可封驳中书省的规划方案（打回修改）
- 可封驳尚书省提交的代码审查（打回重做）
- 最多 3 轮封驳，第 3 轮强制通过并记录风险

### 尚书省
- 只在门下省准奏后才能派发任务
- 负责协调六部并行执行
- 执行完成后提交门下省做代码审核
- 代码审核通过后回奏中书省

### 编排器（workflow-runner）
- 拥有调用所有技能的特权（编排器专属）
- 通过 Agent 子进程派发各步骤
- 不直接执行业务逻辑，只负责调度和状态跟踪
- 由皇上或 Scrum Master 触发

### 六部执行层
- 只接受尚书省派发的任务
- 不能直接找中书省或门下省
- 执行完成后只向尚书省回报
- 编码类任务必须通过 Agent 子进程使用 Claude Code Edit/Write 工具执行

## 敏捷模式权限（保留不变）

敏捷模式下不使用此权限矩阵，由 Scrum Master 自由协调各技能。
