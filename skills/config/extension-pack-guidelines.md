# 外部技能包迁移规范

本文件定义把第三方技能组迁移进 Scrum Skills 时必须遵守的设计约束。

## 1. 迁移目标

迁移的目标不是“把上游仓库整个塞进来”，而是做到：

1. 核心技能组安装后即可用，不被外部依赖拖垮。
2. 上游能力尽量保留，便于后续继续同步。
3. 用户能用中文快速理解每个迁移包和关键命令的作用。
4. 自动编排边界清晰，不把未适配的技能硬接进主流程。

## 2. 目录与元数据

每个外部技能包至少要有：

- 目录本体：保留上游核心文件和运行时
- `.source.json`：记录来源仓库、版本/提交、同步时间
- `pack.json`：声明宿主兼容、依赖边界、能力标签、工作流接入策略
- `SKILL.md` 或包级入口说明：告诉用户这个包整体做什么
- 中文目录说明：列出高频命令、使用时机、额外依赖

如果上游已经有完整运行时，不要为了“看起来统一”就拆碎重组。

`pack.json` 最低需要覆盖：

- `name` / `kind`
- `source`
- `hosts`
- `runtime.dependencies`
- `capabilities`
- `workflow_integration`
- `docs.zh_cn`
- `security`

## 3. 中文化规则

中文化不等于重写上游所有内容，最少必须做到：

1. 包级说明用中文描述
2. README 或中文命令目录中，给出高频命令的中文作用
3. 说明哪些命令适合独立调用，哪些不会进入 `0-workflow-runner`
4. 说明额外依赖和启用步骤

推荐格式：

| 命令 | 作用 | 何时使用 | 额外依赖 |
|------|------|----------|----------|
| `/review` | 审查代码变更 | 准备提交或合并前 | 无 |

## 4. 依赖边界

- 核心技能组：只依赖系统自带 `sh` / PowerShell
- 可选扩展包：可以有 `bun`、浏览器、Playwright 等依赖，但必须明确标为可选
- 禁止把可选扩展依赖写进核心安装前置条件
- 禁止让核心安装脚本自动执行扩展包 setup

## 5. 自动编排边界

外部迁移包默认按“独立调用”处理，除非已经完成以下适配：

1. 命令语义与 Scrum Skills 角色体系兼容
2. 输入输出可纳入现有共享文档和状态流
3. 失败处理、依赖要求、执行时间可以被编排器接受
4. 已补充中文说明与测试路径

未满足前，README 必须明确写出“不接入自动编排”。

## 6. 更新策略

同步上游时按这个顺序：

1. 更新 `.source.json`
2. 更新 `pack.json`
3. 检查目录结构或 setup 流程是否变化
4. 检查中文目录说明是否失效
5. 检查 README 中的依赖和启用步骤是否仍然成立
6. 必要时补充迁移差异说明

## 7. 本仓库当前实践

- `The Minimalist Entrepreneur`：拆成独立技能，保留原命令名，补中文描述与 `.source.json`
- `gstack`：整仓 vendoring，保留原 setup 与运行时，额外补中文命令目录，不默认启用
