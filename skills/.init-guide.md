# 技能组初始化引导

**本文件定义了技能组的自动初始化流程**

## 初始化检测

所有技能在执行任务前，首先检查初始化状态：

```markdown
## 🔍 初始化检测

检查 `PROJECT_CONFIG.md` 初始化状态...

- 检查文件是否存在
- 检查是否包含 `initialized: true` 标记
- 检查必填项是否已填写
```

## 初始化状态

### 未初始化

如果检测到以下任一情况，判定为未初始化：

- ❌ `PROJECT_CONFIG.md` 不存在
- ❌ 配置文件中 `initialized: false`
- ❌ 项目名称为默认值（"你的项目名称"）
- ❌ 必填项未填写

### 已初始化

如果满足以下所有条件，判定为已初始化：

- ✅ `PROJECT_CONFIG.md` 存在
- ✅ 配置文件中 `initialized: true`
- ✅ 项目名称已填写
- ✅ 技术栈已配置
- ✅ 业务域已定义

#### 技术栈识别规则

**前端框架识别：**
- 检查 `package.json` 中的 dependencies
  - `"vue": "^3.x"` → Vue 3
  - `"react": "^18.x"` → React 18
  - `"@angular/core": "^16.x"` → Angular 16
- 检查配置文件
  - `vite.config.js` → Vite
  - `webpack.config.js` → Webpack
  - `vue.config.js` → Vue CLI

**后端框架识别：**
- 检查 `pom.xml`（Java）
  - `<artifactId>spring-boot-starter-web</artifactId>` → Spring Boot
- 检查 `package.json`（Node.js）
  - `"@nestjs/core"` → NestJS
  - `"express"` → Express
- 检查 `requirements.txt`（Python）
  - `Django` → Django
  - `Flask` → Flask

**数据库识别：**
- 检查配置文件
  - `application.yml` 或 `application.properties`
  - `spring.datasource.url=jdbc:mysql` → MySQL
  - `spring.redis.host` → Redis
- 检查 `docker-compose.yml`
  - `image: mysql` → MySQL
  - `image: postgres` → PostgreSQL
  - `image: mongo` → MongoDB

**架构模式识别：**
- 检查目录结构
  - `domain/`, `application/`, `infrastructure/` → DDD
  - `controller/`, `service/`, `repository/` → 分层架构
  - `models/`, `views/`, `templates/` → MVT（Django）

#### 业务模块识别规则

**Java项目：**
- 扫描 `src/main/java/com/{company}/{project}/` 下的顶层包
- 每个包名对应一个业务域
- 例如：`com.shop.product` → product（商品管理）

**Node.js项目：**
- 扫描 `src/modules/` 或 `src/domains/` 目录
- 每个子目录对应一个业务域

**Python项目：**
- 扫描 `apps/` 或 `modules/` 目录
- 每个子目录对应一个业务域

**前端项目：**
- 扫描 `src/views/` 或 `src/pages/` 目录
- 每个子目录对应一个业务模块

**业务域描述生成：**
- product → 商品管理
- order → 订单管理
- user → 用户管理
- payment → 支付管理
- logistics → 物流管理
- customer → 客户管理
- article → 文章管理
- comment → 评论管理

### 增量更新规则

**何时触发增量更新：**
1. 检测到 git 有新提交
2. 上次扫描时间超过24小时
3. 用户手动触发更新

**增量更新流程：**

```markdown
## 🔄 增量更新流程

### 步骤1：获取变更文件列表
使用 git diff 获取变更文件：

```bash
# 获取最近N次提交的变更文件
git diff --name-only HEAD~N HEAD

# 或者获取自上次扫描以来的变更
git diff --name-only {last_scan_commit} HEAD
```

### 步骤2：过滤相关文件
只分析可能影响配置的文件：

**需要分析的文件：**
- ✅ Java源码：`src/main/java/**/*.java`
- ✅ 前端页面：`src/views/**/*.vue`
- ✅ 配置文件：`pom.xml`, `package.json`, `application.yml`
- ✅ 数据库脚本：`*.sql`

**忽略的文件：**
- ❌ 测试文件：`**/*Test.java`, `**/*.spec.js`
- ❌ 文档文件：`*.md`, `*.txt`
- ❌ 构建产物：`target/`, `dist/`, `node_modules/`

### 步骤3：分析变更内容
只读取变更文件，分析影响：

**新增业务域：**
- 检测新增的顶层包或目录
- 例如：`src/main/java/com/shop/payment/` → 新增 payment 域

**新增API端点：**
- 检测新增的 Controller 类
- 分析 `@RequestMapping` 注解

**新增数据模型：**
- 检测新增的 Entity 类
- 分析字段和关系

### 步骤4：增量更新配置
只更新变更部分，不重写整个文件：

```yaml
# 在 PROJECT_CONFIG.md 中追加新业务域
business_domains:
  - name: "product"
    description: "商品管理"

  - name: "payment"  # 新增

# 更新最后扫描时间
