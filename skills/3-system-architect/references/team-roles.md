# 团队角色职责

## 角色定义

### 业务专家 (business-expert)

**职责：**
- 梳理业务流程和业务规则
- 提供领域知识和业务洞察
- 定义业务术语和概念
- 验证业务逻辑正确性

**输出物：**
- 业务流程文档
- 业务规则清单
- 领域模型概念

**协作方式：**
- 与产品经理协作定义需求
- 为架构师提供业务背景
- 参与需求评审和验收

### 产品经理 (product-manager)

**职责：**
- 需求分析和文档化
- 编写用户故事
- 定义验收标准
- 需求优先级排序

**输出物：**
- 需求分析文档
- 用户故事列表
- 验收标准清单

**协作方式：**
- 从业务专家获取业务知识
- 与架构师讨论技术可行性
- 向开发团队传达需求

### 系统架构师 (system-architect)

**职责：**
- 整体架构设计
- 技术方案决策
- 任务拆解和分配
- 技术风险评估

**输出物：**
- 架构设计文档
- 技术方案
- 任务分解清单
- 风险评估报告

**协作方式：**
- 协调所有角色工作
- 技术指导和评审
- 解决技术难题

### 后端开发 (backend-dev)

**职责：**
- 领域模型实现
- API 接口开发
- 数据库设计
- 业务逻辑编码

**输出物：**
- 后端代码
- API 文档
- 数据库脚本
- 单元测试

**协作方式：**
- 与前端开发定义 API 契约
- 与架构师确认技术方案
- 与测试团队配合测试

### 前端开发 (frontend-dev)

**职责：**
- 页面组件开发
- 状态管理实现
- API 集成
- 用户交互实现

**输出物：**
- 前端代码
- 组件文档
- 集成测试

**协作方式：**
- 与后端开发对接 API
- 与 UI 设计师确认设计
- 与测试团队配合测试

### UI 设计 (frontend-design / nielsen-ui-design)

**职责：**
- 界面设计
- 交互设计
- 视觉规范制定

**输出物：**
- 设计稿
- 交互原型
- 设计规范文档

**协作方式：**
- 与产品经理确认需求
- 与前端开发交付设计
- 参与设计评审

### 测试 (webapp-testing)

**职责：**
- 测试用例编写
- 功能测试执行
- 质量保证
- 缺陷跟踪

**输出物：**
- 测试用例
- 测试报告
- 缺陷清单

**协作方式：**
- 与产品经理确认验收标准
- 与开发团队反馈问题
- 参与需求评审

## 协作流程

**需求阶段：**
业务专家 → 产品经理 → 系统架构师

**设计阶段：**
系统架构师 → UI 设计师 → 开发团队

**开发阶段：**
后端开发 ↔ 前端开发 ↔ 测试团队

**验收阶段：**
测试团队 → 产品经理 → 业务专家
