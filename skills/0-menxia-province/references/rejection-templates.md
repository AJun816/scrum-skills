# 封驳模板

**门下省封驳时使用的标准模板和常见封驳原因。**

---

## 封驳报告模板

```markdown
## 🔍 门下省封驳报告

**审核阶段：** {阶段1: 需求 / 阶段2: 架构 / 阶段3: 代码}
**封驳轮次：** 第 {N}/3 轮
**审核文档：** {文档路径}

### 封驳原因

1. **{问题标题}**
   - 问题描述：{具体问题}
   - 影响范围：{影响哪些功能/模块}
   - 修改建议：{具体的修改方向}

2. **{问题标题}**
   - 问题描述：{具体问题}
   - 影响范围：{影响哪些功能/模块}
   - 修改建议：{具体的修改方向}

### 已通过项
- {通过的检查项列表}

### 修改要求
- [ ] {修改项1}
- [ ] {修改项2}

---
请根据以上意见修改后重新提审。
```

## 常见封驳原因

### 阶段 1：需求封驳

| 原因 | 说明 | 修改建议 |
|---|---|---|
| 需求遗漏 | 未覆盖皇上旨意的某个需求点 | 补充遗漏的需求描述和用户故事 |
| 验收标准缺失 | 用户故事没有明确的验收标准 | 为每个故事添加可测试的验收标准 |
| 需求歧义 | 需求描述不清晰，可能有多种理解 | 明确描述，消除歧义 |
| 边界缺失 | 未考虑异常场景和边界条件 | 补充异常流程和边界处理 |

### 阶段 2：架构封驳

| 原因 | 说明 | 修改建议 |
|---|---|---|
| 技术选型不当 | 选择的技术与项目不兼容 | 重新评估技术选型 |
| 安全风险 | 存在明显的安全漏洞 | 补充安全设计方案 |
| 性能瓶颈 | 设计存在明显的性能问题 | 优化数据模型或查询方案 |
| API 不规范 | 不符合 RESTful 规范 | 按规范重新设计 API |

### 阶段 3：代码封驳

| 原因 | 说明 | 修改建议 |
|---|---|---|
| 功能未实现 | 代码未实现需求中的某个功能 | 补充实现 |
| 文件超标 | 单文件超过 800 行 | 拆分文件 |
| 安全漏洞 | 存在 OWASP Top 10 漏洞 | 修复安全问题 |
| 硬编码密钥 | 代码中包含硬编码的密钥 | 改用环境变量 |
| 缺少测试 | 没有对应的测试用例 | 补充测试 |
