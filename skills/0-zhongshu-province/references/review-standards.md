# 提审前自检标准

**中书省在提交门下省审核前，必须完成以下自检。**

---

## 需求文档自检

| 检查项 | 标准 | 必须 |
|---|---|---|
| 需求完整性 | 覆盖皇上旨意的所有需求点 | ✅ |
| 用户故事 | 每个功能点有对应的用户故事 | ✅ |
| 验收标准 | 每个用户故事有明确的验收标准 | ✅ |
| 优先级 | 需求按优先级排序 | ✅ |
| 边界条件 | 异常场景和边界条件已考虑 | ✅ |
| 非功能需求 | 性能、安全、兼容性要求已明确 | ⚠️ |

## 架构设计自检

| 检查项 | 标准 | 必须 |
|---|---|---|
| 技术选型 | 技术栈选择有理有据 | ✅ |
| 模块划分 | 模块职责清晰，边界明确 | ✅ |
| 数据模型 | 数据库设计合理，字段完整 | ✅ |
| 接口设计 | API 路径、参数、返回值明确 | ✅ |
| 安全设计 | 认证、授权、数据加密方案 | ✅ |
| 扩展性 | 设计支持未来扩展 | ⚠️ |
| 依赖分析 | 外部依赖已识别和评估 | ⚠️ |

## API 设计自检

| 检查项 | 标准 | 必须 |
|---|---|---|
| RESTful 规范 | 路径、方法、状态码符合规范 | ✅ |
| 请求参数 | 参数类型、必填、默认值明确 | ✅ |
| 返回格式 | 统一的响应格式 | ✅ |
| 错误处理 | 错误码和错误信息定义 | ✅ |
| 版本管理 | API 版本策略 | ⚠️ |

## 自检流程

1. 逐项检查上述清单
2. 必须项（✅）全部通过才能提审
3. 建议项（⚠️）尽量满足，未满足需说明原因
4. 自检结果记录到提审文档中
