# 初始化检测流程

**本文件定义技能组如何检测和处理初始化状态**

## 检测流程

### 第一步：检查缓存文件

```markdown
## 🔍 检测初始化状态

检查缓存文件：`skills/.cache/.project-info.json`

- 文件存在 → 之前已初始化过
- 文件不存在 → 需要初始化
```

### 第二步：判断场景

#### 场景1：缓存存在（已初始化）

```markdown

你好！检测到这个项目之前已经初始化过了。

**项目信息：**
- 项目名称：{从缓存读取}
- 初始化时间：{从缓存读取}
- 上次使用：{从缓存读取}

现在告诉我你想做什么吧！
```

**处理逻辑：**
1. 读取缓存文件 `.cache/.project-info.json`
2. 读取配置文件 `PROJECT_CONFIG.md`
3. 更新 `last_used` 时间戳
4. 直接开始工作

#### 场景2：缓存不存在（未初始化）

```markdown
## 🎯 欢迎使用敏捷团队技能组！

检测到这是第一次使用技能组，我会帮你快速初始化项目配置。

整个过程只需要 **2分钟**，回答 **3个简单问题** 即可。

准备好了吗？

**选项：**
- ✅ 是的，开始初始化
- 📖 先看看配置示例
- ⏭️ 跳过，稍后手动配置
```

**处理逻辑：**
1. 启动初始化引导流程
2. 收集项目信息
3. 生成配置文件
4. 创建缓存文件

#### 场景3：配置文件存在但缓存不存在

```markdown
## 🔄 检测到配置文件

发现了项目配置文件，但缓存文件不存在。

可能的原因：
- 手动创建了配置文件
- 缓存被清除了
- 从其他地方复制了配置

我会根据现有配置文件重建缓存。

**配置信息：**
- 项目名称：{从配置读取}
- 技术栈：{从配置读取}
- 业务域：{从配置读取}

配置看起来正确吗？

**选项：**
- ✅ 正确，继续使用
- ✏️ 修改配置
- 🔄 重新初始化
```

**处理逻辑：**
1. 读取 `PROJECT_CONFIG.md`
2. 验证配置完整性
3. 根据配置生成缓存文件
4. 继续工作

#### 场景4：缓存存在但配置文件不存在

```markdown
## ⚠️ 配置文件丢失

检测到缓存文件存在，但配置文件 `PROJECT_CONFIG.md` 不存在。

可能的原因：
- 配置文件被误删
- 文件路径错误

**缓存中的项目信息：**
- 项目名称：{从缓存读取}
- 初始化时间：{从缓存读取}

你想要：
- 🔄 根据缓存恢复配置文件
- 🆕 重新初始化
- ⏭️ 跳过（使用默认配置）
```

**处理逻辑：**
1. 读取缓存文件
2. 根据缓存信息恢复配置文件
3. 或者重新初始化

## 缓存文件结构

### .cache/.project-info.json

```json
{
  "project_name": "电商平台",
  "initialized": true,
  "initialized_at": "2024-02-12 16:00:00",
  "last_used": "2024-02-12 17:30:00",
  "config_version": "1.0",
  "cache_version": "1.0",
  "tech_stack": {
    "frontend": "Vue 3",
    "backend": "Spring Boot",
    "database": "MySQL"
  },
  "business_domains": ["product", "order", "user", "payment", "logistics"]
}
```

**字段说明：**
- `project_name` - 项目名称
- `initialized` - 是否已初始化
- `initialized_at` - 初始化时间
- `last_used` - 最后使用时间
- `config_version` - 配置文件版本
- `cache_version` - 缓存文件版本
- `tech_stack` - 技术栈摘要
- `business_domains` - 业务域列表

## 检测代码逻辑（伪代码）

```python
def check_initialization():
    """检测初始化状态"""

    cache_file = "skills/.cache/.project-info.json"
    config_file = "skills/PROJECT_CONFIG.md"

    cache_exists = file_exists(cache_file)
    config_exists = file_exists(config_file)

    # 场景1：缓存存在（已初始化）
    if cache_exists and config_exists:
        cache = read_json(cache_file)
        update_last_used(cache_file)
        return {
            "status": "initialized",
            "message": f"欢迎回来！项目 {cache['project_name']} 已准备就绪。",
            "action": "continue"
        }

    # 场景2：缓存不存在，配置不存在（未初始化）
    if not cache_exists and not config_exists:
        return {
            "status": "not_initialized",
            "message": "欢迎使用！让我帮你快速初始化项目配置。",
            "action": "start_init"
        }

    # 场景3：配置存在但缓存不存在
    if not cache_exists and config_exists:
        config = read_config(config_file)
        create_cache_from_config(config)
        return {
            "status": "cache_rebuilt",
            "message": "已根据配置文件重建缓存。",
            "action": "continue"
        }

    # 场景4：缓存存在但配置不存在
    if cache_exists and not config_exists:
        cache = read_json(cache_file)
        return {
            "status": "config_missing",
            "message": "配置文件丢失，是否根据缓存恢复？",
            "action": "restore_config"
        }

def update_last_used(cache_file):
    """更新最后使用时间"""
    cache = read_json(cache_file)
    cache["last_used"] = current_timestamp()
    write_json(cache_file, cache)
```

## 0-scrum-master 特殊职责

作为敏捷教练，0-scrum-master 负责：

1. **初始化检测**
   - 第一个被调用时，执行初始化检测
   - 根据检测结果引导用户

2. **初始化引导**
   - 如果未初始化，启动引导流程
   - 收集项目信息
   - 生成配置文件
   - 创建缓存文件

3. **配置验证**
   - 验证配置完整性
   - 检查必填项
   - 提示缺失项

4. **缓存管理**
   - 创建缓存文件
   - 更新缓存信息
   - 清理过期缓存

## 缓存更新时机

### 自动更新

- 每次技能启动时，更新 `last_used` 时间
- 配置文件修改时，同步更新缓存
- 业务域变更时，更新缓存中的业务域列表

### 手动更新

用户可以手动触发缓存更新：

```
用户：/refresh-cache

技能：
🔄 刷新缓存

读取配置文件...
更新缓存信息...

✅ 缓存已更新
- 项目名称：{更新后的值}
- 技术栈：{更新后的值}
- 业务域：{更新后的值}
```

### 清除缓存

用户可以清除缓存重新初始化：


## 总结

通过缓存检测机制，技能组实现了：

1. **智能检测**
   - 自动识别是否已初始化
   - 区分首次使用和重新打开

2. **无缝体验**
   - 重新打开Claude窗口无需重新初始化
   - 自动加载项目配置
   - 直接开始工作

3. **容错处理**
   - 配置文件丢失可恢复
   - 缓存文件损坏可重建
   - 多种异常场景处理

4. **用户友好**
   - 清晰的状态提示
   - 明确的操作指引
   - 最小化用户操作

**核心理念：** 让技能组像记忆一样，记住项目信息，无需重复配置。
